Bundled runtime libraries (the *.dll files next to the executable)
------------------------------------------------------------------
The Windows bundle carries the mingw-w64 DLLs the executable links at runtime.
They are DYNAMICALLY linked, so the LGPL components remain replaceable by the
recipient — the build deliberately does NOT pass a bare `-static` for exactly
that reason (libs/vgui/vgui.v, #318): mingw's FreeType is built with HarfBuzz,
which pulls in GLib, and absorbing an LGPL-2.1+ library into the executable
would ask far more of the distributor than shipping it beside one. GLFW and the
GCC runtime are the exceptions, static by explicit flag and both permissive.

The authoritative list is whatever ldd resolves at build time (see
.github/workflows/windows.yml); the packages installed for that build are:

  FreeType           FTL / GPL-2    https://freetype.org/
  HarfBuzz           MIT            https://harfbuzz.github.io/
  GLib / GObject     LGPL-2.1+      https://gitlab.gnome.org/GNOME/glib
  FriBidi            LGPL-2.1+      https://github.com/fribidi/fribidi
  Fontconfig         MIT-style      https://www.freedesktop.org/wiki/Software/fontconfig/
  libpng             PNG/zlib       http://www.libpng.org/             (via FreeType)
  zlib               zlib           https://zlib.net/                  (via FreeType/libpng)
  mingw-w64 runtime  ZPL / MIT-like https://www.mingw-w64.org/         (libgcc/libstdc++/libwinpthread)

To obtain the source for any LGPL/GPL component bundled here, see the upstream
project link above, or contact the distributor.
